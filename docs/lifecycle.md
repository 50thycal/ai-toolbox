# Lifecycle and evidence

| Stage | Meaning | Selection guidance |
| --- | --- | --- |
| discovered | Saved; not meaningfully evaluated | Research if relevant |
| reviewed | Purpose, requirements, and limitations understood | Candidate for a scoped pilot |
| piloting | Being evaluated in a named project | Use within that experiment's scope |
| toolbox | Successful representative pilot and reusable setup documented | Preferred candidate when compatible |
| paused | Blocked or awaiting evidence | Read blocker before considering |
| rejected | Evaluated and unsuitable for the documented need | Preserve reason; reconsider only with new evidence |
| retired | Previously useful, now replaced or no longer supported | Prefer recorded replacement |

Stages are confidence labels, not an irreversible sequence. A regression may move a tool from Toolbox to Paused. A tool can be Toolbox for one documented use while untested or unsuitable elsewhere.

## Evidence for promotion

A documentation review supports Reviewed. A pilot record names the app, version, date, flow, environment, result, and remaining limitations. Toolbox requires a successful representative pilot plus a reproducible recipe. Compare runtime, cost, and maintenance when those motivated the tool choice.

Record failed attempts and the reason for changes in history. Never promote a tool merely because an AI recommended it, installed it, or liked its README.

## Freshness

Review current upstream guidance before first integration, upgrades, or consequential decisions. Revisit an entry after failures or major upstream changes. The review date and tested version make stale evidence visible; no recurring update job is configured by this starter.
