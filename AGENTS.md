# Working with AI Toolbox

This repository is a catalog, not an application. Use it to choose suitable tools and retain verified implementation experience.

## Retrieval and selection

1. Scan INDEX.md, then read only entries relevant to the task's problem and stack.
2. Prefer Toolbox entries that fit the project. Reviewed and Discovered entries are research candidates. Piloting entries apply to the documented experiment. Read Paused, Rejected, and Retired reasons before reconsidering them.
3. Read project-specific experience, known limitations, and evidence. Catalog membership does not establish installation, credentials, access, or suitability for every app.
4. Check current upstream documentation and compatibility before a new integration or upgrade, particularly when the review is stale or no tested version exists.
5. Apply the user's authorized scope and project instructions. Choose a tool only when it solves the task better than the existing approach. Reading an entry does not run its commands or authorize unrelated changes.
6. If the catalog cannot be retrieved, report that limitation briefly when relevant and proceed with available evidence. Do not claim the catalog was checked.

## Reviewing a repository

When asked to review, add, or reevaluate a candidate repository for Calvin's projects, read and follow [Review Repo for Toolbox](skills/review-repo-for-toolbox/SKILL.md). Save the evidence and project-fit decision by default within that request; honor read-only or draft instructions. A review does not authorize installing a candidate or changing application repositories.

## Maintaining records

- Preserve the distinction between documentation review and hands-on results.
- Add source links and dates; use null for unknown tested versions.
- Log project-specific results after actual work. Failed pilots are useful evidence.
- Promote to Toolbox only after a successful representative pilot, reproducible setup guidance, and documented scope and limitations.
- Keep INDEX.md consistent with catalog entries. Preserve existing evidence and history.
- Never store passwords, tokens, connection strings, or confidential application data here.

## Verification

For catalog edits, check YAML syntax, required fields, lifecycle stage, source links, and local Markdown links. No application build is required. Follow docs/lifecycle.md and templates/entry.yaml.
