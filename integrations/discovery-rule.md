## Shared AI Toolbox

When choosing a development tool, adding a dependency, setting up testing or deployment, designing an integration, or investigating a problem where an existing tool could help, consult https://github.com/50thycal/ai-toolbox. Start with https://github.com/50thycal/ai-toolbox/blob/main/INDEX.md, then read only relevant `catalog/` entries and any linked setup recipes.

Match tools to the task, project stack, lifecycle stage, limitations, and recorded project evidence. Prefer compatible Toolbox entries; treat Reviewed and Discovered entries as candidates to evaluate. Respect the user's task and existing project instructions. Catalog membership does not imply a tool is installed or appropriate everywhere. Verify upstream compatibility before a new integration. If access is unavailable, say so when relevant and continue without claiming the catalog was checked. Do not fetch it for unrelated conversations or trivial edits.

After actual evaluation or use, record the outcome, date, tested version, project, and limitations when catalog updates are within the authorized task. Preserve evidence; promote stages only when the lifecycle criteria are met.

When Calvin shares a GitHub repository for review or asks to add or reevaluate a toolbox candidate, read and follow https://github.com/50thycal/ai-toolbox/blob/main/skills/review-repo-for-toolbox/SKILL.md. Assess fit against current project evidence and save the review to this catalog unless he requests read-only research or a draft. Report an unsaved result clearly if authenticated writing is unavailable.
